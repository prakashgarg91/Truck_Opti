## 🚨 IMPORTANT RULES

### Rule 1: Always Sign In First
```
Before ANY work:
1. Add yourself to "Who's Online Now?" table
2. Post a message saying what you plan to do
3. Check if anyone else is working on same files
```

### Rule 2: Announce Before Editing
```
Before editing a file, post:
"I am editing [filename] for [reason]"

This prevents two AIs editing same file simultaneously.
```

### Rule 3: Test Before Push
```
MANDATORY before git push:
1. Run: npm test
2. Verify: ALL tests pass (338+)
3. Post: "Tests passed, pushing to GitHub"
4. Then push
```

### Rule 4: Sign Out When Done
```
When finished working:
1. Post summary of what you did
2. Change status to 🔴 Offline
3. Include any handoff notes for next AI
```

## 🔄 GIT PUSH PROTOCOL

### Before Pushing to GitHub

```bash
# Step 1: Run ALL tests
npm test
# Must see: "Tests: 338 passed (338)"

# Step 2: Post in DISCUSSION.md
"[timestamp] AI-NAME: Tests passed (338/338). Pushing changes."

# Step 3: Stage and commit
git add -A
git commit -m "type: description"

# Step 4: Push to GitHub FIRST
git push origin main

# Step 5: Push to Heroku (if needed)
git push heroku main

# Step 6: Post confirmation
"[timestamp] AI-NAME: Successfully pushed to GitHub/Heroku"
```

### Commit Message Format
```
type: short description

Types:
- feat: New feature
- fix: Bug fix
- refactor: Code restructure
- test: Test changes
- docs: Documentation
- chore: Maintenance
```

## 💡 TIPS FOR SMOOTH COORDINATION

1. **Check discussion FIRST** - Before starting any work
2. **Post frequently** - Other AIs need to know what you're doing
3. **Small commits** - Easier to track and review
4. **Test often** - Don't accumulate untested changes
5. **Clear handoffs** - Next AI shouldn't have to guess

## 🚫 NEVER DO

| Never | Why |
|-------|-----|
| Push without testing | Breaks production |
| Edit without announcing | Causes conflicts |
| Leave without signing out | Others don't know status |
| Skip discussion updates | Coordination fails |
| Push to Heroku before GitHub | Loses sync |
